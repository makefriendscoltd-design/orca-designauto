# 상세페이지 디자인 시스템

기존 산출물 4종을 실측해 뽑은 것. **새로 만들지 말고 여기 있는 걸 먼저 쓴다.**

## 0. 먼저 읽을 것 — AI slop 을 피하는 법 (26-07-29, 시안 4번 반려 끝에 정리)

시안을 네 번 갈아엎고 나온 결론이다. **여기부터 지키지 않으면 나머지는 소용없다.**

### 절대 쓰지 않는 것

| 금지 | 이유 |
|---|---|
| `radial-gradient` 배경, 사선 광선(comet) | v0·Lovable 등 코드 생성기의 1번 특징 |
| 네온색 + `text-shadow` 글로우 | 지금 가장 AI 같은 조합 |
| 그라디언트 테두리 카드 (`padding:2px` 래퍼) | 코드 생성기 서명 |
| 격자 배경 오버레이 | 위와 동일 |
| 생성한 글로시 3D 오브젝트 (로봇·코인 등) | AI 이미지의 대표 클리셰 |
| 액센트 3색 이상 | 셋이면 싸구려로 보인다 |
| 모든 요소 `border-radius:20px` + 가운데 정렬 | 긴장이 없다 |
| 사진에 grayscale + 어두운 베일 | 템플릿 처리 |
| 모든 섹션이 `eyebrow → 제목 → 카드 3개` | 같은 박자의 반복 |

공통점은 하나다. **전부 "빛"으로 만든 디자인**이다 — 그라디언트·글로우·투명도.
잘 만든 상세페이지는 **"잉크"로 만든다** — 단색 면, 하드 엣지, 큰 활자, 실사진.

### 대신 쓰는 것

- **단색 면**과 **1px 괘선**으로만 구획을 나눈다
- 액센트는 **브랜드 계열 하나**. 다크 면은 리듬용으로 2곳까지
- **실사진을 크게.** 인물 누끼가 템플릿 느낌을 깨는 가장 강한 수단이다
- 서체는 **한 벌**로. 장식 폰트를 섞으면 촌스러워진다

### 검증된 재료 (전부 무료 상업용)

| | 출처 | 용도 |
|---|---|---|
| **Wanted Sans** | `github.com/wanteddev/wanted-sans` (OFL) | 본문·제목 전부. **Black(900)** 이 있어 Pretendard 800으로 안 되던 무게가 나온다 |
| **Pretendard** | `github.com/orioncactus/pretendard` (OFL) | 기존 페이지 호환용 |
| **Radix Colors** | `github.com/radix-ui/colors` (MIT) | 12단계 스케일. `slate`(중립) + 브랜드색 + 강조색 1개 |
| BM한나체 / 여기어때 잘난체 | 시스템 기본 설치 | **말풍선 속말 전용.** 본문에 쓰면 촌스러워진다 |

릴리스 zip 에서 `webfonts/static/complete/woff2/` 만 꺼내 `assets/fonts/` 에 넣는다.
Radix 는 `unpkg.com/@radix-ui/colors@3.0.0/<scale>-dark.css` 에서 `@supports` 앞부분(sRGB)을 파싱한다.

## 0-1. 공간 체계 — 몰입감의 8할

유저 피드백 "이미지가 다닥 붙어있고 공간감이 없다"로 재설계한 값. **줄이면 바로 티가 난다.**

| | 값 |
|---|---|
| 섹션 상하 패딩 | **200px** (예전 120px 은 답답하다) |
| 좌우 마진 | 90px → 콘텐츠 900px |
| 제목 ↔ 본문 | 44px |
| 본문 ↔ 다음 요소 | 88px |
| 나열 항목 간격 | 46~58px + 괘선. **절대 붙이지 않는다** |
| 본문 행간 | 1.75~1.85 |
| 풀블리드 이미지 앞뒤 | 150px 이상 |
| 한 문장만 놓는 몰입 판 | 상하 **260px** |

**한 판에 한 메시지.** 스크롤하다 멈추는 지점을 2~3곳 만든다 (다크 풀블리드 한 문장 / 거대 수치).

## 0-2. 스토리텔링 순서

**제 주장으로 시작하지 않는다.** 독자가 자기 욕구를 확인할 자리를 먼저 준다.

```
상황묘사(내 얘기다) → 속말 말풍선(못 할 것 같다) → 욕구(이런 걸 원했다)
→ 지목(그래서 당신은 아직 ○○다) → 진단(왜 안 됐나) → 전환(그래서 이렇게 바꿨다)
→ 증거 → 오퍼
```

### 말풍선 + 캐릭터 (한국 커머스 상세페이지 표준 장치)

독자의 속말을 먼저 꺼내놓고 뒤에서 받아준다. **구매 저항이 올라오는 순서대로** 3개까지.

1. **능력 의심** — "나는 뭘 만들 줄 모르는데"
2. **지속력 의심** — "하다 막히면 또 포기할 텐데"
3. **신뢰 의심** — "또 녹화본만 주는 거 아냐" ← 제일 크다

멘트는 **시장조사로 뽑는다.** 소비자원 피해통계·커뮤니티 후기·실사용 블로그를 검색해
실제로 나오는 문장을 쓴다. 지어내면 티가 난다.

구현: 연블루 면 + 흰 말풍선(`border-radius:34px` + `::before/::after` 로 꼬리) +
손글씨 폰트 + 3D 캐릭터 누끼. 캐릭터는 **matte clay 스타일**로 생성하면 slop 을 피한다
(글로시 sci-fi 는 금지).

### 누끼 따기

배경이 단색/그라디언트면 채널 차이로 키잉한다. 파란 배경이면 `B-R` 로 알파를 만들고 디스필.
흰 배경이면 **테두리에서 플러드필** — 인물 내부의 흰옷을 보존하려면 이 방식이어야 한다.

## 공통 코어 — 네 페이지가 전부 공유

`wrap` `hero` `eyebrow` `lead` `hl` `cta`

이 여섯은 브랜드 정체성이다. 색만 갈아끼우고 구조는 건드리지 않는다.

```
.wrap    width:1080px 고정
.hero    다크 그라디언트 + comet 광선. 브랜드 → 배지 → h1 → sub → 사실 4칸
.eyebrow 24px/700, 액센트색. 섹션마다 h2 위에 한 줄
.lead    30px/500, mute색. h2 아래 본문 리드
.hl      h2 뒷줄에 거는 하이라이트. 밑에서 58~92% 밴드
.cta     액센트 풀블리드. 제목 → 일시/가격 → 버튼 → 마지막 한 줄
```

`hl` 은 **다크 배경 위에서는 밴드를 좁힌다**(76~96%). 넓으면 갈색 블록처럼 뭉쳐 글자가 묻힌다.

## 유형별 표준 구조

### 무료 웨비나·특강 모집 (8~10섹션 / 7,000~9,000px)

```
HERO(다크)          배지에 일시를 박는다 · whenbar 4칸
문제 제기            pains 카드 3~4 + 마무리 한 줄
다크 선언            "이 특강의 관점" — 왜 다른가
구조                machine 4단계 + 마무리 한 줄
다루는 것            topics 2×2, machine 라벨 재사용
신청자 혜택(다크)     bonus — 최대 전환 장치
적합/부적합          fitgrid
누가 진행하나         tutor
CTA(액센트)          일시 pill → 0원 → 버튼 → 마지막 한 줄
```

**신청자 혜택 섹션이 이 유형의 심장이다.** 무료 웨비나는 참석 부담이 진입 장벽이라
"참석하지 못하셔도 신청만 하시면 받으실 수 있습니다"가 신청률을 만든다.
이게 없으면 지금 신청할 이유가 없는 페이지가 된다.

### 무료 전자책·리드마그넷 (7~8섹션)

```
HERO → 문제제기 → 데이터/신뢰 → 다크선언 → 담긴 내용 → 보너스 → FAQ → CTA
```
FAQ에 **"진짜 0원인가요"**를 반드시 넣는다. 무료의 최대 의심이다.

### 유료 디지털 상품 (12~13섹션)

```
HERO → rise(인상밴드) → 문제제기 → 데이터 → 다크선언 → cmp(무료vs유료)
→ parts(커리큘럼) → vault(전용무기) → fitgrid → bonus → guar(보증) → FAQ → CTA
```
무료본이 이미 있으면 **cmp 비교표가 필수**. "무료 봤는데 왜 또 사?"가 최대 반박이다.

### 유료 클래스 (8~10섹션)

```
HERO(다크) → pricetop(가격) → value(제공가치) → 문제제기
→ band+커리큘럼(주차) → tutor → CTA(다크)
```

## 지식 상품 상세페이지의 업계 관습

와디즈·월급쟁이부자들 등 지식 상품 플랫폼에서 공통으로 쓰는 것.
**우리 페이지에 아직 약한 부분**이라 의식적으로 챙긴다.

### 1. 후기를 위로 올린다

월부는 **베스트 후기가 페이지 최상단**이다. 소개보다 먼저 온다.
그리고 **규모를 숫자로 보여준다** — 총 37,244개 · 평점 4.9 · 별점 분포 · 성별/연령 분포.

우리 페이지는 후기가 없거나 링크 텍스트뿐이다. 후기가 생기면:
- 개수와 평점을 숫자로 박는다
- 실명/닉네임 + 연령대 + 성별을 함께 (익명 후기는 신뢰가 낮다)
- 원문 링크를 걸어 검증 가능하게 한다

### 2. 강사는 3인칭 경력이 아니라 1인칭 스토리

월부 강사 소개는 경력 나열 뒤에 **"저 역시 지도조차 볼 줄 몰랐습니다"** 같은
before 서사가 붙는다. 수강생과 같은 출발점이었다는 증명이 경력보다 강하다.

`tutor` 컴포넌트에 넣을 것: 경력 3~5줄 → **1인칭 스토리 문단** → 실적 3칸.

### 3. 커리큘럼은 3단으로 촘촘하게

월부는 `강사 → N강 → 강별 세부 불릿 3~4개`. 한 강의에 60줄이 넘는다.
문단 6개로 끝내면 얇아 보인다. **세부 불릿까지 내려간다.**

### 4. 사실 정보는 표로 먼저

수강 기간 / 구성(총 N개 수업) / 수강 조건을 본문 앞 박스에 정리한다.
설득 전에 "이게 뭔지"가 3초 안에 잡혀야 한다.

### 5. 길다고 팔리지 않는다

와디즈 공식 가이드의 결론 — 특징이 많고 페이지가 길수록 구매와 직결되지는 않는다.
와디즈는 **오프닝 → 브릿지(3문장 요약) → 본문(특징 5개 요약 → 특징별 상세) → 클로징** 4단.
브릿지에서 **전체를 3문장으로 요약**하고 들어가는 게 핵심이다.

우리 페이지엔 이 브릿지가 없다. HERO 다음에 바로 문제제기로 간다.
**HERO `sub` 를 3문장 요약으로 쓰면** 같은 효과를 낸다.

## 섹션 마무리 한 줄 패턴

레퍼런스가 일관되게 쓰는데 놓치기 쉬운 것. **섹션 끝마다 회색 한 줄**로 의미를 못박는다.

```
"강의력이 부족한 게 아닙니다. 강의 밖의 일이 전부 수동이라 그렇습니다."
"한 단계라도 끊기면 다음 기수는 다시 0에서 시작합니다"
"툴을 나열하는 시간이 아닙니다. 제가 실제로 돌리고 있는 흐름을 공개합니다."
```

카드만 나열하고 끝내면 독자가 스스로 결론을 내야 한다. 한 줄로 대신 내려준다.

## 카피 규칙

- **이모지 금지.** AI 티의 8할이 이모지다
- **구어체.** "~하실 수 있습니다" → "~하면 됩니다 / ~돼요"
- **방어 가능한 숫자만.** 과장된 배수 대신 실측치
- h1/h2는 2줄, 뒷줄에 `hl`. 한 줄짜리 긴 제목은 임팩트가 죽는다
- 문제 제기는 고객이 실제로 쓰는 문장으로 — "조회수가 늘 세 자리에서 안 넘어간다"
- **부적합 목록에 진짜 비추천을 쓴다.** 형식적으로 쓰면 역효과, 진짜로 쓰면 환불·클레임이 준다
