# 레퍼런스 재구현 방식 — 2026-09-30 확정 사례

기준 결과물: `landing/ebook-concept-ecommerce-v10/`. v8 방향을 사용자가 최고로 평가한 뒤 v9에서 대비·간격을 조정하고 v10에서 최신 3D 표지와 설명 이미지를 반영했다. 이 문서는 해당 사례의 재사용 원칙이며, 모든 상품에 동일 치수를 강제하는 템플릿이 아니다.

## 레퍼런스를 코드로 옮기는 범위

색만 가져오지 않는다. 실제 상세 이미지 영역을 찾아 캔버스 폭, 섹션 순서, 문장별 줄바꿈, 타이포 위계, 자간·행간, 문구↔애셋 간격, 애셋의 화면 점유율, 배경 전환, 그라데이션, 광원, 이모지, FAQ와 CTA까지 측정한다. 이번 예시는 430px 캡처의 본문398px를740px로 출력했다. 모든 크기는 논리폭과 출력폭을 구분한다.

- 제목·본문·비교 문구의 역할을 먼저 정한다. 단순히 폰트를 바꾸지 말고 비교 전후의 크기·굵기·색·거리로 대비를 확실히 만든다.
- 사례에서는 기존 표현18px/400, 개선 표현43px/800, 본문 행간1.42, 답변1.45, 강조 자간-0.025em을 사용했다.
- 섹션 끝·다음 시작 패딩과 연결선 마진이 합산되는지 본다. 같은 주장과 이미지를 멀리 떨어뜨리지 않는다. v9는 카피를 줄이지 않고 v8 높이를15.6% 줄였다.
- 애셋은 CSS 박스가 아니라 실제 보이는 내용의 점유율로 측정한다. SVG viewBox 내부 공백도 포함해 확인한다.
- 실사형 이미지는 의미에 맞는 상품/사용자/상황/구매구조 설명용으로 쓴다. 텍스트가 길게 이어지는 구간에 제목→관련 이미지→설명 순서를 만든다. 사진을 성과 증거로 오해하게 만들지 않는다.
- 원문 자료의 이미지를 우선한다. 생성 이미지나 예시 화면은 실제 사용성과/후기로 포장하지 않는다.

## 기존 성과 증빙을 먼저 보존한다

- 리디자인 전에 기존 상세 HTML, 첨부 자료, `assets/proof`, `reviews`, `kakao`와 인수인계 기록에서 성과·후기·저자 지표를 목록화한다. 책 본문만 읽고 새 카피를 쓰지 않는다.
- 각 자료의 파일 경로, 실제 화면의 지표명·수치·기간, 사례 주체, 기존 사용 문맥과 새 배치 위치를 기록한다. 프로필 조회수와 게시글 조회수, 자사 성과와 독자 성과를 구분한다.
- 검증 가능한 기존 자료를 일반적인 사용 예시로 대체하거나 설명 없이 삭제하지 않는다. 출처나 연결이 불확실하면 확인할 항목으로 남기고 원문과 이전 사용자 지시를 찾는다.
- 큰 핵심 수치 → 읽을 수 있는 원본 캡처 → 대상·기간을 밝힌 짧은 설명으로 구성한다. 실제 증빙을 보장 문구로 확대하지 않으며, 일괄적인 면책 문구로 성과의 의미를 지우지도 않는다.
- 재구성 후 기존 증빙 목록과 실제 HTML 이미지 참조를 대조한다. 기존 자료마다 유지·이동·중복 통합·제외 사유가 있어야 검수 완료로 본다. 제외는 근거가 있어야 하며 단순 누락은 실패다.
- 기존 마스킹본을 우선 사용하고 고객 이름·연락처·주문정보가 새로 드러나지 않게 확인한다.

## 새 표지를 놓치지 않는 방법

사용자가 재제작했다고 하면 옛 PNG 경로만 확인하지 않는다. 소유 프로젝트의 최신 컴포넌트, 브리프, handoff/배포기록을 함께 비교한다. 이번 정본은 패밀리라운지 BookCover 컴포넌트의 3D 표지이며, 옛 cover_cut.png는 폐기했다. 기존 네이티브 컴포넌트를 headless 렌더해 가져오고 임의 재생성하지 않는다. 표지 출처·표시제목·해시를 기록하고 상단/하단 모든 사용처가 같은 파일을 참조하는지 검사한다.

## 산출과 검수

1. 승인 버전 보존 후 새 폴더에서 수정. 편집 정본은 HTML/CSS/원본 애셋.
2. 실제 Chrome 렌더, 폰트/이미지 로드·가로 넘침 검사.
3. 전체4~6구간과 바뀐 곳 원본 크기 확인. 의미단위 줄바꿈과 한 단어 고립을 검사.
4. 같은 배율 전후 비교. 레퍼런스 이미지/타사 인물·실적은 판매물과 Git 패키지에서 제외.
5. 안전한 배경행에서 슬라이스. 높이합과 모든 조각의 픽셀을 전체 렌더와 대조.
6. 가격·상품번호·수령·CTA를 운영 정본과 확인. 게시 요청 시 해당 운영 작업공간에서 기존 설명 백업→이미지 업로드→description/mobile_description만 변경→독립 API 및 공개 PC/모바일 확인.
7. 원문/고객데이터/시크릿/배포 백업을 통째로 Git에 넣지 않는다. 정본·사용애셋·재현도구·안전한 검증요약만 커밋한다.

사용자의 명시적 디자인 요구(예: 그라데이션·이모지)가 범용 스킬의 금지 취향보다 우선한다. 시각적 검증 없이 완성 선언하지 않는다.

## 2026-10-01 랜딩페이지 후속 교정

- 사용자 지적: 라운지·카페 회원수는 랜딩 제작법의 실력을 증명하지 못한다. 공통 권위라고 자동 삽입하지 않는다. 책 주제와 직접 연결되는 자료만 선택한다.
- 사례는 텍스트·박스만 연속시키지 않는다. 관련 상황/제품/사용 이미지와 핵심 카피를 한 덩어리로 배치하고, 짧은 해설을 연결한다. 생성 사진은 실제 성과 증빙과 구분해 표시한다.
- 레퍼런스의 작은 리드→큰 결론→넓은 이미지→설명 비율을 코드로 적용한다. 좁은 좌측 문서형 구성을 고급 디자인이라고 자동 판단하지 않는다. v5는 사용자 승인 전 수정안이다.
