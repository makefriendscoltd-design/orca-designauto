# 상철의 전자책 헤드카피 기준

2026-09-30 사용자 직접 수정 및 “공식화시켜서 계속 적용연습” 요청으로 확정.
적용 범위는 이 프로젝트의 전자책 상세페이지. 새 상품의 숫자·성과·약속을 만들어내는 근거가 아니다.

## 기본형: 원하는 결과 → 수단 → 상품 형태

`[고객이 원하는 구체적 결과] + [그 결과에 접근하는 수단] + [실제 상품 형태]`

승인 예: **유튜브 1만 / AI로 만드는 / 비법서**

- 결과: 유튜브 1만. 고객이 사고 싶은 도착점을 먼저 말한다.
- 수단: AI로. 방법의 차이를 짧게 붙인다.
- 형태: 비법서. 무엇을 받는지 분명하게 닫는다.
- “기획부터 대본까지 AI 비서에게 맡기세요”는 작업 기능 설명이다. 헤드 아래에서 방법을 설명할 때 사용한다.
- 책에 맞는 결과와 수단을 고른다. 모든 상품에 ‘1만’, ‘AI’, ‘비법서’를 반복하지 않는다.

## 대안형: 독자의 실패 상황 → 원인 직격

성과보다 독자의 막힌 지점이 강한 상품에는 `[계속 하는데 안 되는 일] + [원인에 대한 직접적인 진단]`을 쓴다.

승인 예: **스레드 아무리 써도 안팔린다면 / 그건 100% 글 문제입니다**

‘100%’는 해당 상품에 사용자가 지정한 문구다. 다른 상품의 원인이나 결과를 100%라고 자동 단정하지 않는다.

## 실제 수정 사례 — 새 작업 전에 비교할 것

| 구분 | 약했던 표현 | 사용자가 선택한 표현 | 재사용할 판단 |
|---|---|---|---|
| 유튜브 메인 | 기획부터 대본까지 / AI 비서에게 / 맡기세요 | 유튜브 1만 / AI로 만드는 / 비법서 | 작업 목록보다 독자가 원하는 결과가 먼저 |
| 스레드 메인 | 수정 전 문구는 이 표에 미수록 | 스레드 아무리 써도 안팔린다면 / 그건 100% 글 문제입니다 | 지금 겪는 실패를 짚고 원인을 바로 말하기 |
| 매출 권위 | 실제 사업을 운영하며 / 쌓아 온 기록 | 블로그 마케팅으로 / 매출을 만들어온 곳 + 누적 114.9억 | 실적이 이 책을 신뢰할 이유가 되도록 주제와 연결 |

마지막 행은 ASIDE의 권위 섹션 사례다. 회사 전체 매출을 특정 채널만의 매출로 바꾸지 않는다. 현재 승인된 누적 기간은 2021.01~2024.04이며 정본은 `landing/ebook-aside-blog-v3/qa/cumulative-revenue-verification.json`이다. 해당 회사 자료를 사용하는 경우만 참조한다.

## 작성과 적용 연습

1. 카피를 쓰기 전에 **독자가 원하는 결과 / 실제 방법 / 상품 형태 / 사용 가능한 근거**를 각각 한 줄로 적는다.
2. 내부적으로 결과형·문제진단형·기존 기능설명형을 짧게 비교한다. 사용자에게 여러 안을 매번 고르게 하지 말고, 상품과 근거에 가장 맞는 안을 골라 실제 히어로에 적용한다.
3. 선택안이 “좋은 글”, “AI 활용”, “업무를 맡기기”처럼 포괄적인 설명에 머물면 한 번 더 쓴다. 고객이 얻고 싶은 변화가 첫 줄에서 보이는지 확인한다.
4. 사용자 지정 숫자·문구는 그대로 반영한다. 근거 없이 새 수익·기간·달성 보장·원인 단정을 덧붙이지 않는다. 승인된 판매 헤드와 과거 성과 증빙은 별도로 구분한다.
5. 결과 키워드를 가장 크게, 수단·상품명을 다음 크기로 둔다. 긴 수식어와 설명은 서브카피로 보낸다. 줄바꿈은 의미 단위로 나누고 렌더에서 한눈에 읽히는지 확인한다.
6. 사용자가 카피를 고치면 **이전 문구 → 사용자 문구 → 달라진 판단**만 이 표에 추가한다. 내 초안이나 자기평가를 사용자 승인 사례로 넣지 않는다.

## 렌더 직전 짧은 점검

- 첫 줄이 작업 설명인가, 독자가 원하는 결과/현재 문제인가?
- 숫자가 있다면 이 상품에서 승인되었거나 확인한 숫자인가?
- 수단과 상품 형태가 바로 읽히는가?
- 가장 중요한 결과가 가장 크게 보이는가?
- 불필요한 마침표·장식 기호·긴 수식어를 빼도 뜻이 유지되는가?
- 작은 보조 문구가 강한 헤드와 실적의 의미를 다시 흐리고 있지 않은가?

상품별 `copy.md`에는 최종 카피를, `qa`에는 선택한 공식과 근거 및 실제 렌더 확인 결과를 짧게 남긴다. 별도의 자기평가 점수나 과도한 보고서를 만들지 않는다.

## 2026-10-01 랜딩페이지 교정

사용자는 “전환율이 높아지는/팔리는 랜딩페이지 제작법”처럼 상품의 결과와 구체적 제작법을 요구했다. 기존 “방문자를 구매자로 바꾸는 상세페이지 설계 비법서”는 약하다고 지적했다. 권위와 실제 자료를 뒤로 밀거나 추상 질문으로 대체하지 않는다. 첫 화면 다음에 실적 근거, 본문에는 실제 원문·완성 예제·제작 단계를 보여준다. 최종 v3 조합 문구는 아직 사용자 승인 전이다.
