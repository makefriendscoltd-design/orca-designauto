# 전자책 상세페이지

전자책 자체를 편집하는 스킬이 아니라, 전자책을 배포하거나 판매하기 위한 상세페이지를 만드는 스킬이다. HTML/CSS와 구조화 브리프가 정본이고 이미지 산출물은 파생물이다.

## 1. 상품 정본을 찾는다

대상 폴더에서 기존 HTML, 브리프, 상품 설명, 최신 렌더를 찾고 아래 값을 한 곳에서 확정한다.

- 제목과 한 줄 정의
- 무료·유료 여부, 정가와 판매가
- PDF·EPUB 등 형식, 페이지 수, 업데이트일
- 대상과 해결할 실제 문제
- 목차와 핵심 결과물
- 무료 샘플 또는 무료판과의 차이
- 보너스, 수령 방식, CTA
- 저자 소개와 검증 가능한 증거

없는 수치·후기·성과는 만들지 않는다. 값이 충돌하면 최신 파일명을 근거로 임의 선택하지 않는다.

## 2. 디자인 문법을 고른다

| 조건 | 문법 | 폭 | 도구 |
|---|---|---:|---|
| 별도 스타일 지시 없음 | 범용 전자책 상세 | 1080px | `$detail-page`, `$detail-launch` |
| 와디즈·포스터형 레퍼런스 | 포스터 연작 | 860px | `$poster-detail` |
| 프드프형, 증거·후기 중심 유료 상품 | 정보형 세일즈 레터 | 740px | `$pudufu-detail` |

선택한 도구의 `SKILL.md`와 필요한 참조만 읽는다. 폭, CSS, 슬라이스 규격을 섞지 않는다.

## 3. 무료와 유료를 다르게 설계한다

- 무료 전자책: 무엇을 받는지, 누구에게 필요한지, 진짜 무료인지, 수령 방법을 짧게 해결한다.
- 유료 전자책: 무료 정보와 다른 점, 목차의 깊이, 실제 적용 결과, 적합·부적합, 보너스, 환불·FAQ를 해결한다.
- 무료판이 따로 있으면 유료판과의 비교를 반드시 보여준다.
- 페이지 수를 신뢰의 근거로 쓸 때는 실제 최종 파일과 일치시킨다.
- 외부 자료로 숫자·최신 동향·제품 성능·법률·재무·인과 주장을 새로 단정하면 초안 전에 `$content-research-gate`를 사용한다.

## 4. 편집 정본을 만든다

- 새 상품은 `landing/<ebook-slug>/`에 둔다.
- 로컬 폰트, 고정폭, `word-break: keep-all`, `print-color-adjust: exact`를 유지한다.
- 표지·내지·실제 목차·사용 화면을 우선하고 가짜 책 목업이나 가짜 후기를 증거처럼 만들지 않는다.
- 이미지 속 작은 글씨에 메시지를 맡기지 않고 큰 캡션으로 핵심을 설명한다.
- 사용자의 명의로 나가는 한국어 카피는 초안 후 `$humanize-korean`으로 의미 보존과 문체를 점검한다.

## 5. 렌더와 QA

1. 선택한 정본 스킬의 기존 렌더러로 전체 이미지를 만든다.
2. 썸네일은 요청되었거나 판매 산출물에 필요할 때만 만든다.
3. 전체 이미지를 4~6구간으로 나눠 직접 본다.
4. 폰트 폴백, 넘침, 줄바꿈, 목차·가격·페이지 수·수령 방식, CTA를 확인한다.
5. 글자가 잘리지 않게 슬라이스하고 폭·순서·합계 높이를 검사한다.
6. 운영값이 여러 파일에 있으면 `$launch-consistency-check`로 대조한다.

완료 보고에는 편집 정본, 전체 렌더, 썸네일 여부, 슬라이스, 직접 본 QA, 미검증 항목을 포함한다. 카페24 등록·외부 발행·발송은 수행하지 않는다.
