## 폭은 740px 다 — 절대 넓히지 말 것 (26-08-03)

**"모바일 최적화가 안 됐다 · 가독성이 떨어진다 · 와디즈 스타일이 아니다"** 피드백으로 전면 재조판했다.
원인은 폰트 크기가 아니라 **캔버스 폭**이었다.

이미지 상세는 모바일에서 화면 폭(≈390px)에 맞춰 통째로 축소된다. 캔버스가 넓을수록 더 축소된다.

| | 와디즈 740px | 옛 우리 1080px |
|---|---|---|
| 모바일 축소율 | 0.527배 | 0.361배 |
| 본문 25px 이 | **13.2px** 로 보임 | **9.0px** 로 보임 |

**와디즈 상세(FundingStory) 실측 폭이 740px 다.** 크롬 devtools 로 직접 쟀다.
폭을 넓히면 같은 폰트가 그대로 작아지고, 한 줄 글자 수가 늘어 시선 복귀 거리도 길어진다.

### 폰트는 "제목을 줄이고 본문을 유지"한다

1080 때 제목/본문 비율이 **3.4배(84:25)** 라 제목만 읽히고 본문은 개미였다. 740 에서 **1.9배(46:24)**.

| | 1080판 | 740판 | 모바일 체감 |
|---|---|---|---|
| hero h1 | 84 | 46 | 24.2px |
| h2 | 72 | 44 | 23.2px |
| lead | 29 | 26 | **13.7px** |
| 본문 | 25 | 24 | **12.6px** |
| 최소(사실칸 라벨) | 19 | 20 | **10.5px** |

본문 24px · 리드 26px 가 하한선이다. 보조 텍스트 색도 `#5b6478` → `#54607a` 로 진하게 했다.

### 740 에서 깨져서 바꾼 것

- **사실 4칸 → 2×2** (4칸이면 칸당 185px 라 라벨이 접힌다)
- **증거 스크린샷 2단 → 세로 1단** (2단이면 칸당 303px 라 캡처 속 글자가 죽는다)
- **정원 10명 가로 2단 → 세로** · **CTA 알약 3+1 → 2+2**(`max-width:420px`)
- **강사 섹션 좌우 반전** — 누끼 하단이 잘려 있어 다크 면 위에서 도드라진다.
  HERO 처럼 텍스트 왼쪽 · 사진 오른쪽 하단정렬로 두면 밑동이 텍스트 블록과 만나 티가 안 난다
- **HERO `min-width:0`** — 없으면 1fr 의 min-content 가 h1 전체 폭이라 사진이 캔버스 밖으로 잘린다.
  1080판은 이 버그를 안고 라이브였다

**`detail_startup_schedule.html` 도 740 으로 같이 옮겼다.** 폭이 다르면 이어 붙일 때 그 장만 튄다.
렌더에 `--width 740` 을 반드시 붙인다.

## 스토리 순서는 와디즈 4단이다 (26-08-03)

폭만 고쳤을 때 유저가 **"후킹이랑 스토리라인이 잘 잡힌 게 맞냐"** 고 물었고, 재보니 아니었다.
와디즈는 `오프닝 → 브릿지 → 본문(요약→상세) → 클로징` 인데 우리는 공감 서사가 앞을 다 먹고 있었다.

| | 재배열 전 | 재배열 후 |
|---|---|---|
| 공감·문제제기 | **8~30%** | 33~49% |
| 증거·후기 | 30~46% | **7~27%** |
| 구성 요약 | 없음 | **27~33%** |
| 상품 상세 | 46~70% | 49~76% |

**"이게 뭐고 진짜 되는구나"가 46% → 33% 로 당겨졌다.**

신설 2개 · 삭제 3개:
- **`후기` 신설** (와디즈 1원칙 — 후기를 최상단). 아래 절 참조
- **`구성 요약 5개` 신설** (와디즈 본문 1단). 옛 `가져가는 것` 을 이 자리로 끌어올려 대체
- 삭제 — `욕구(want)` 3칸(상황묘사와 중복) · `말풍선 2`(뒤의 5개월 운영이 이미 답을 함) · `가져가는 것`
- **말풍선 3개 → 2개.** 능력 의심 / 신뢰 의심만 남겼다
- **90% 판을 다크로** 바꿨다. 흰 섹션이 연달아 오는 구간의 리듬을 끊는다

배경 리듬 주의 — **`정원 10명` 섹션은 흰색이어야 한다.** 바로 뒤 `구성 요약`이 tint 라
둘 다 tint 면 경계가 사라진다. 앞의 풀블리드 사진이 구분자 역할을 한다.

### 후기 — 소재와 수치 근거

유저가 26-08-03 에 카페 캡처로 제공했다.

- **인용은 발췌만.** 원문(3기 후기글, 26-07-07)을 통째로 옮기지 않는다.
  닉네임 · 기수 · 날짜를 붙여 검증 가능하게 둔다
- **"30건 +"** 는 결과물 목록에서 `AIMAX 창업프로그램` 이 제목에 명시된 것만 센 **37건의 하한**이다.
  부동산 계열 등 태그 없는 글은 뺐다. **올려 쓰지 말 것**
- 기수는 **1 · 2 · 3기** 까지 확인됨

### 결과물 월(wall) — 프레임은 "이만큼 쏟아진다"

카페 게시글 19건을 `기수 · 제목 · 닉네임 · 날짜` 로 옮겨 놓은 블록이다.
스크린샷은 모바일에서 글자가 죽으니 **읽히는 텍스트로 한 번 더** 놓는다.
닉네임·날짜가 있어야 카페 원문과 대조가 된다.

**"한 사람이 두세 개씩 만들었다"로 쓰지 말 것 (26-08-03 유저 지적).**
목록에 같은 닉네임이 반복되는 걸 그렇게 설명하면 **수강생이 적어 보이는 역효과**가 난다.
프레임은 `업종도 목적도 전부 다르다` + `정원 10명 기수에서 매번 이만큼 나온다` 다.

통계 2칸도 같은 프레임 — `30건 +` / **`기수당 10개 +`**.
정원 10명 × 3기수에 30건 이상이면 1인 1서비스 이상이고, 90% 제작 성공과 맞물린다.

## 와디즈판은 「웹페이지」가 아니라 「포스터 연작」이다 (26-08-09)

**이 문법은 `poster-detail` 스킬로 굳혔다.** 다른 상품에 이식할 땐 스킬을 먼저 연다 —
키트(`poster.css`·`SKELETON.html`)·실측 스크립트·반려 방지 체크리스트가 다 거기 있다.
아래는 이 상품 고유의 실측값과 결정 이력이다.

**V5~V7 이 세 번 연속 반려된 이유가 이거다.** 색만 갈아끼우고 레이아웃 문법은 그대로 둬서
매번 "디자인이 똑같다"는 지적을 받았다. 레퍼런스와 **같은 배율로 나란히 붙여 실측**하고 나서야
원인이 잡혔다 — 문제는 팔레트가 아니라 **타입 스케일과 한 화면당 메시지 수**였다.

### 실측값 (와디즈 410104, 860px 캔버스)

제목 글자의 잉크 높이 **126px**, 행간 **164px** → 폰트 크기 환산 **약 150px**.
그때 우리 판은 50px 이었다. **정확히 3배 차이.**

| | 레퍼런스 | 반려된 V7 | 채택된 V8 |
|---|---|---|---|
| 제목 | ~150px | 50px | **140px** |
| 중간 | ~90px | 25px | **92px** |
| 보조 | ~78px | 19px | **72px** |
| 한 화면당 메시지 | **1개** | 3~5개 | **1개** |
| 정렬 | 가운데·세로 | 왼쪽 | 가운데·세로 |

### 반드시 들어가는 시각 어휘

이게 없으면 아무리 색을 맞춰도 "그냥 웹페이지"로 보인다.

- **검정 박스 반전 강조** — 다크 면에선 흰 박스에 검은 글씨(`.markb`). **한 줄에 들어가게** 크기를 줄일 것.
  2줄로 터지면 거대한 흰 슬래브가 되어 망한다 (V8 1차 렌더에서 실제로 터졌음)
- **형광 박스 강조** — 파란/민트 배경 인라인 박스(`.marku` `.markm`)
- **알약 뱃지** — 섹션 라벨은 아이브로우 텍스트가 아니라 `border-radius:999px` 알약
- **✦ 반짝이** · **이중 쉐브론 연결자** · **원형 스텝 도트**
- **radius 28px 라운드 다크 카드** (각진 박스 금지)
- **민트 → 다크 곡선 전환** (`border-radius:0 0 70px 70px` + 음수 마진)
- **STEP = 썸네일 + 큰 텍스트 2단** (번호+본문 리스트 아님)

**쉐브론은 글리프(⌄ ≫)를 쓰지 말고 CSS 보더로 그린다.** 폰트에서 가늘게 나와 존재감이 없다.

## 서체 — 7종 웨이트가 다 있다 (26-08-09 확인)

`assets/fonts/` 에 **Regular 400 · Medium 500 · SemiBold 600 · Bold 700 · ExtraBold 800 ·
Black 900 · ExtraBlack** 이 전부 있다. 오래 3종(500/700/900)만 쓰고 있었다 — 포스터 제목엔
ExtraBlack 을 쓸 수 있다.

**BM한나체는 말풍선 속말 전용.** 본문에 절대 쓰지 않는다.

## 카페 모집글용은 상세페이지와 반대 원칙이다

상세페이지는 날짜를 **빼서** 재사용하지만, 카페 모집글은 기수마다 새 글이라
**날짜를 박는 게 맞다.** 대신 손으로 안 고치고 스크립트로 뽑는다.

```bash
python3 make_cards.py    --gen 5 --label 9월반 --first 2026-09-06   # 카페 첨부 (기본)
python3 make_timeline.py --gen 5 --label 9월반 --first 2026-09-06   # 롱이미지
```

### 카페엔 롱이미지가 아니라 카드 3장을 쓴다

**처음에 1080×5,439 롱이미지로 만들었다가 유저 지적으로 카드형을 따로 지었다.**
롱이미지는 상세페이지 포맷이다 — 카페 본문에 넣으면 모바일에서 한참 스크롤한다.
카페는 본문에 글을 쓰고 이미지는 **한 화면에 훑히는 카드**여야 한다.

| | 카페 카드 | 롱이미지 |
|---|---|---|
| 크기 | 1080×1350 × **4장** | 1080×5,991 × 1장 |
| 쓰는 자리 | **카페 글 흐름 중간에 나눠 박음** | 상세페이지·노션처럼 길게 읽는 자리 |
| 담는 것 | 1 전체 흐름 / 2 오프라인 2주 / 3 매일·매주·매달 / 4 복습 라이브 커리큘럼(다크) | 전부 한 장에 |

카드 장수가 바뀌면 `make_cards.py` 의 `N_CARDS` 와 `SUBTITLES` 도 같이 고친다.

**4:5 인 이유** — 카페는 모바일이 주력이고 세로 4:5 가 화면을 가장 크게 먹는다.
가로형은 모바일에서 축소돼 글씨가 안 읽힌다.

`cards_startup.html` 의 `.card` 는 **height 1350px 고정**이다. 내용을 늘리면 조용히
잘리므로 `make_cards.py` 가 렌더 높이를 4,050 인지 검사하고 다르면 멈춘다.
우하단 워터마크(`.mark`)와 겹치기 쉬운 자리라 고친 뒤엔 세 장 다 눈으로 볼 것.

### 날짜가 박히는 건 오프라인 2회뿐이다

| 값 | 규칙 | 5기(9월반) |
|---|---|---|
| 오프라인 2주 (5h+5h) | `--first` · `+7일` | **9/6 · 9/13 (일) · 매회 12~17시** |
| 온라인 | **날짜 없음** — "오프라인 다음 주부터 · 5개월 · 매일·매주·매달" | — |
| 1:1 컨설팅 | **날짜 없음** — "요청 시" (시점 안 박음) | — |

**라이브 요일·시간을 날짜로 바꾸지 말 것 (26-07-30 유저 확정).**
기수마다 정해지는 값이라 이미지에 박으면 매번 클레임 소재가 된다.
처음엔 "8월 24일부터 매주 월요일"로 박았다가 지웠다. 순서만 보여주고
`.memo` 로 "요일과 시간은 기수 시작 전에 안내합니다" 한 줄을 단다.

시간대가 바뀌면 `--t1` / `--t2`.
치환이 1건이 아니면 스크립트가 **즉시 멈춘다** — 옛 날짜가 박힌 이미지가 나가는 게
제일 위험해서 그렇게 짰다. HTML 구조를 고치면 `make_timeline.py` 의 정규식도 같이 고칠 것.

**마스터는 항상 `timeline_startup.html`.** 스크립트가 만드는 `_timeline_Ngi.html` 은
렌더 성공하면 지워진다.

### 「상품 간략설명」이 곧 SEO 설명이다

`simple_desc` 가 **`meta description` · `og:description` · JSON-LD `description`** 으로 그대로 나간다.
여기에 상품명을 복사해두면 검색 결과와 카톡 공유 미리보기가 상품명 두 줄이 된다.
**내용을 담은 한 줄**을 쓴다. `additional_description_translated` 도 같이 고칠 것.

| 항목 | 값 |
|---|---|
| 이미지 | 21장 3,074KB, 5MB 초과 없음 → **한 번에 업로드** |

같은 이름으로 다시 올리면 서버가 `copy-<epoch>-s0.jpg` 사본을 만들고, 캐시 때문에
바뀐 게 맞는지 눈으로 확인할 수가 없다.

**옛 파일은 서버에 그대로 남는다.** 되돌리려면 `v3_*` / `v2_*` / `s*` URL 로 HTML만 다시 주입하면 된다.

옛 이미지 `NNEditor/20260715/a2c865b601b0bb29442012e70e01886e.jpg` 는 서버에 남아 있어
되돌리려면 그 URL 한 장만 다시 넣으면 된다.
